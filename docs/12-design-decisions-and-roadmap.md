# 12 — قرارات الاعتماد قبل SQLite
## الحالة
هذه مخططات ERD تفصيلية مقترحة؛ **لم تتحول بعد إلى جداول SQLite تشغيلية**. الملفات الأصلية 00–07 محفوظة.
## أهم نقاط تحتاج تثبيتًا
1. أسماء أعمدة Stk_Item: في المخططات القديمة ParentId؛ تجنب الخلط مع ParentItemId.
2. تثبيت DocTyp والقيم 1..7 وفق المستندات السابقة، بما فيها سند صرف 5 وقبض 6.
3. اختيار ربط مصدر Yomia: JournalEntries + DocumentRegistry موحد أم SourceId/Typ مع تحقق برمجي.
4. تحديد تمثيل الأموال: INTEGER أصغر وحدة نقدية أو تمثيل عشري مضبوط مع التحقق.
5. علاقة Invoice ItemUnit: مفتاح مركب يثبت ملكية الوحدة للصنف.
6. تعريف سياسات الترحيل والمرتجعات والتسويات والتحويل والجرد والرصيد السالب.
7. تحديد ما إذا كان التطبيق فرعًا واحدًا في النسخة الأولى؛ مخطط Branches يدعم التوسع.
## خطوات التنفيذ
1. مراجعة واعتماد الجداول والأسماء والمفاتيح مع المهندس صلاح.
2. كتابة قاموس بيانات مفصل وأنواع SQLite وCHECK وUNIQUE والفهارس.
3. إنشاء migrations SQL واختبارات foreign_key_check وintegrity_check.
4. إدخال دليل حسابات وأصناف افتراضي.
5. برمجة الترحيل والمعاملات والقيود والمخزون.
6. تصميم Android ثم تشغيل المحاكي واختبارات السيناريوهات.
